Escopo de Usuário e Pacotes Portáteis

Instalar “só para mim” ou “para todos”? E onde vai parar um programa que não tem instalador? Esta aula abre a caixa do pacote portátil.

Você vai aprender
  • A diferença entre --scope user e --scope machine.
  • Onde o winget guarda um pacote portátil e o atalho dele.
  • Por que o comando só funciona num terminal aberto depois da instalação.
Sobre as saídas. Todas as saídas desta aula vieram do winget rodando no Windows de verdade (winget v1.29.380 | Windows 10.0.19045.0 | idioma da interface pt-BR | PowerShell 7.7.0 | 2026-11-21 12:49). Um script de coleta rodou cada comando, um por um, e gravou a resposta exata; antes de gravar, o nome do computador virou NOTEBOOK, o da pessoa virou a usuária fictícia ana (pasta C:\Users\ana) e endereços de rede viraram exemplos. As mensagens aparecem no idioma do Windows em que foram colhidas, exatamente como o winget escreveu: nunca traduzimos nem inventamos saída. Os títulos das tabelas e as mensagens podem estar em outro idioma no seu computador, e os números de versão mudam com o tempo.
O pacote de teste

Todas as aulas deste nível usam o jq (jqlang.jq), um programa de linha de comando para ler JSON, com cerca de 1 MB. Ele é portable e fica só na sua conta (--scope user). Use um terminal comum, sem administrador: na coleta deste guia, a sessão de administrador impediu a remoção (aula Desinstalando).

1. Escopo

--scope user
instala só para a sua conta, em pastas dentro de C:\Users\ana; não precisa de administrador.
--scope machine
instala para todas as contas (por exemplo, em C:\Program Files); costuma pedir permissão de administrador.
Escopo de usuário, terminal comum

Instale e remova pacotes de escopo de usuário num terminal comum, sem “Executar como administrador”. Na coleta deste guia, o terminal era de administrador: o install --scope user funcionou, mas o uninstall foi recusado com o código 0x8A15007D (aula Desinstalando).

2. Onde o jq foi parar

Um pacote portátil vai para uma pasta própria dentro de %LOCALAPPDATA%\Microsoft\WinGet\Packages:

PS C:\Users\ana> Get-ChildItem "$env:LOCALAPPDATA\Microsoft\WinGet\Packages" -Directory -Filter "jqlang.jq*" | Select-Object Name

Name
----
jqlang.jq_Microsoft.Winget.Source_8wekyb3d8bbwe

O nome da pasta junta o ID do pacote (jqlang.jq) e o nome da fonte de onde ele veio (Microsoft.Winget.Source_8wekyb3d8bbwe, a fonte winget).

E o winget cria um atalho com o nome do comando na pasta %LOCALAPPDATA%\Microsoft\WinGet\Links, que ele põe no PATH da sua conta. É por isso que basta digitar jq:

PS C:\Users\ana> where.exe jq
C:\Users\ana\AppData\Local\Microsoft\WinGet\Links\jq.exe
PS C:\Users\ana> jq --version
jq-1.8.2

Antes desses dois comandos, a coleta releu o PATH do registro, que é o que acontece num terminal aberto depois da instalação.

Abra outro terminal

O PATH é lido quando o terminal abre. O próprio install avisa: Variável de ambiente do caminho modificada; reinicie seu shell para usar o novo valor. (aula Instalando). Feche e abra o terminal (ou abra outra aba) antes de rodar o comando instalado.

Quando dá errado

Se jq não for reconhecido logo depois de instalar, quase sempre é o PATH antigo do terminal: abra outro. Se continuar, confira se a pasta Links aparece no PATH da sua conta (Configurações › Sistema › Sobre › Configurações avançadas do sistema › Variáveis de Ambiente).

Resumo

  • --scope user instala só para você, sem administrador.
  • Portáteis ficam em WinGet\Packages, com atalho em WinGet\Links.
  • Depois de instalar, abra outro terminal.
