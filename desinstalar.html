Desinstalando (uninstall)

Instalar é só metade. Remover também é um comando, e conferir depois é obrigatório: na coleta deste guia, a remoção falhou, e foi a conferência que mostrou o pacote ainda instalado.

Você vai aprender
  • Remover o jq com winget uninstall.
  • Entender o erro 0x8A15007D: pacote de escopo de usuário num terminal de administrador.
  • Conferir com list e where.exe se o pacote saiu mesmo.
Sobre as saídas. Todas as saídas desta aula vieram do winget rodando no Windows de verdade (winget v1.29.380 | Windows 10.0.19045.0 | idioma da interface pt-BR | PowerShell 7.7.0 | 2026-11-21 12:49). Um script de coleta rodou cada comando, um por um, e gravou a resposta exata; antes de gravar, o nome do computador virou NOTEBOOK, o da pessoa virou a usuária fictícia ana (pasta C:\Users\ana) e endereços de rede viraram exemplos. As mensagens aparecem no idioma do Windows em que foram colhidas, exatamente como o winget escreveu: nunca traduzimos nem inventamos saída. Os títulos das tabelas e as mensagens podem estar em outro idioma no seu computador, e os números de versão mudam com o tempo.
O pacote de teste

Todas as aulas deste nível usam o jq (jqlang.jq), um programa de linha de comando para ler JSON, com cerca de 1 MB. Ele é portable e fica só na sua conta (--scope user). Use um terminal comum, sem administrador: na coleta deste guia, a sessão de administrador impediu a remoção (aula Desinstalando).

1. O comando

winget uninstall --id jqlang.jq --exact --scope user --disable-interactivity --accept-source-agreements
uninstall
remove o pacote.
--id jqlang.jq --exact
exatamente este.
--scope user
a instalação da sua conta.
--disable-interactivity
nada de perguntas no meio.

Rode num terminal comum, sem “Executar como administrador”. A próxima seção mostra por quê.

2. Quando a remoção falha

A coleta deste guia rodou numa sessão de administrador (o PowerShell foi aberto com “Executar como administrador”). O install --scope user funcionou mesmo assim (aula Instalando), mas a remoção, na mesma sessão de administrador, foi recusada:

PS C:\Users\ana> winget uninstall --id jqlang.jq --exact --scope user --disable-interactivity --accept-source-agreements
Encontrado jq [jqlang.jq]
The package installed for user scope cannot be uninstalled when running with administrator privileges.

O winget achou o pacote (Encontrado jq [jqlang.jq]) e parou com o código 0x8A15007D (-1978335107). A mensagem diz que um pacote instalado no escopo de usuário não pode ser desinstalado quando o winget roda com privilégios de administrador. Repare que ela veio em inglês, mesmo com o Windows em português: essa frase não está traduzida nesta versão do winget (v1.29.380).

A causa é a combinação das duas coisas: pacote de escopo de usuário (--scope user) e terminal de administrador. A solução é fechar o terminal de administrador, abrir um terminal comum e rodar a remoção nele:

winget uninstall --id jqlang.jq --exact

A saída desse comando não foi registrada na coleta, por isso o guia não a mostra. Confira o resultado no seu Windows com os comandos da próxima seção.

3. Conferindo: o jq continuou instalado

Logo depois da falha, a coleta conferiu com list e where.exe (este com o PATH relido do registro, como num terminal aberto depois da tentativa):

PS C:\Users\ana> winget list --id jqlang.jq --exact
Nome ID        Versão Origem
-----------------------------
jq   jqlang.jq 1.8.2  winget
PS C:\Users\ana> where.exe jq
C:\Users\ana\AppData\Local\Microsoft\WinGet\Links\jq.exe

O list ainda mostra o jq 1.8.2, e o where.exe ainda acha o atalho jq.exe na pasta WinGet\Links. É assim que se descobre uma remoção que não aconteceu: o código de saída diferente de zero avisa, e o list confirma.

Depois de uma remoção bem-sucedida, os mesmos dois comandos servem de prova: o list responde com a mensagem de pacote instalado não encontrado, a mesma de antes da instalação (aula Listando), e o where.exe não acha mais o jq.

4. O que fica para trás

Num portátil, a remoção apaga a pasta do pacote em WinGet\Packages e o atalho em WinGet\Links (aula Escopo e Portáteis). Se a remoção falha, como aqui, os dois continuam lá. A própria pasta Links continua no PATH da sua conta, vazia ou com atalhos de outros portáteis: é inofensivo. Instaladores tradicionais (msi, exe) seguem as regras do próprio desinstalador e podem deixar configurações na sua pasta de usuário.

Quando dá errado

0x8A15007D com a mensagem sobre user scope e administrator privileges: a sessão é de administrador. Abra um terminal comum e rode o uninstall de novo. Se a resposta for que nenhum pacote instalado corresponde, o pacote já não está lá ou o ID está errado (aula Erros ao Instalar e Remover).

Exercícios

1. Remover

Complete para remover o jq.

winget --id jqlang.jq --exact

2. O uninstall do jq terminou com 0x8A15007D. O que fazer?

Missão: Peça a remoção do jq pelo ID exato, em escopo de usuário e sem perguntas, num terminal comum.

winget uninstall

winget uninstall --id jqlang.jq --exact --scope user --disable-interactivity --accept-source-agreements

Encontrado jq [jqlang.jq]
The package installed for user scope cannot be uninstalled when running with administrator privileges.

Missão: Depois da remoção, confira com list, pelo ID exato, se o jq ainda aparece.

winget list jq

winget list --id jqlang.jq --exact

Nome ID        Versão Origem
-----------------------------
jq   jqlang.jq 1.8.2  winget

Resumo

  • uninstall --id ... --exact remove; rode num terminal comum.
  • Pacote de escopo de usuário + sessão de administrador = 0x8A15007D, e nada é removido.
  • Confira sempre com list e where.exe: foram eles que mostraram o jq ainda instalado.
